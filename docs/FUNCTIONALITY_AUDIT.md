# Functionality Audit — Desktop UI vs. Backend Capabilities

_Last updated: 2026-07-18._

This document compares what the desktop app (`alr.ui.desktop.main_window`) currently
exposes against the capabilities that already exist in the codebase but are **not**
reachable from the UI. It is meant as a backlog for surfacing existing value.

**Session state:** the tool **starts where it was left off** — the storage-path fields (collect, analyze, visualize, evaluate), their custom-path flags, and the Research Area/Question inputs are saved to `ui_session_state.json` when the window closes and restored on the next launch.

**Shell / status:** the window carries a **status strip** under the greeting showing the active **LLM provider + selected model** and whether an **API key** is stored for it (green ●) or missing (red ○) — updated live when the provider, model or key changes, so you see the state before acting instead of only on an error. A top-bar **"Active storage space"** field (Browse) is the single space the **Collect, Analyze, Visualize and Evaluate** tabs default to: each of those tabs has a **"Use active space" toggle** (on by default) that mirrors the active path and locks its own entry, or turns off for a per-tab override; running an analysis **sets the active space to the analyzed folder** so Collect/Visualize/Evaluate auto-point there without re-browsing. **Every user input on every tab** (paths, research area/question, query text, top-k, toggles, provider/model dropdowns, embedding settings, search root, …) is cached to `ui_session_state.json` on close and **pre-filled on the next launch** — the cache is discovered generically from the window's own input widgets (display-only status fields excluded), so new inputs are remembered automatically. On the **Collect** tab the toggle roots the whole CollectionManager tree (keyword / search-phrase / publication / classified-publication lists and logs) under a **`collection` sub-folder of the active space** (`<space>/collection`); untick it to point collection at a custom folder (its tree then lives under `<folder>/collection`), and with neither set it falls back to the default `01_Collection` space. The provider dropdowns everywhere now show **full names** ("Blablador / Chat AI / DLR Ollama") instead of the cryptic `B/C/O` codes. The notebook and the console log sit in a **draggable vertical split** (a `PanedWindow`, replacing the old fixed 60/40 layout) so either can be grown, and a **one-line result label above the console** echoes the last action's outcome (green on success, red on failure/cancel). The console **filters developer-noise lines** (DebugLog banners, separator rules, raw LLM response dumps) by default; a **"Verbose log" checkbox** shows the full raw stream. It is also **bounded**: the widget keeps the most recent 4 000 lines and one poll tick inserts at most ~60 000 characters, so a very chatty pass (a DB build printing per attribute per document) can no longer stall the Tk main loop and freeze the window. The window has a **minimum size**; the main tabs are **Collect · Analyze · Query Execution**, with **Evaluation** and **Enrichment** tucked **browser-style behind a trailing "+" tab** — hidden by default, opened from the "+" menu (or via the Analyze tab's **"Open Evaluation →" / "Open Enrichment →"** buttons, which un-hide + jump), and closed again by right-/control-clicking the tab (the Section Editor lives in the **Review tool**), and a **Help** button explains whichever tab is open. The **progress dialog is non-modal** — other tabs stay browsable while a pass runs — with a **single-task guard** that refuses a second pass until the current one finishes.

Cross-cutting: the **LLM layer** (`llm_utils`) no longer uses thread-based timeouts — every
remote chat/embedding request carries a **native `requests` timeout** (a hung socket raises
cleanly instead of leaking an abandoned worker thread) and **bounded retry-with-backoff** on
429/5xx/network errors (`Retry-After` honoured) *before* any service switch. Cross-service
fallback is **per-call** (`allow_fallback=` on `llm_call`/`embedding_call`): still on by
default for chat but loud, **opt-in (default off) for embeddings** so fallback vectors from a
different embedding space can never silently enter a FAISS index. What actually served each
call (requested vs. used service, model, fallback, errors) is recorded and readable via
`llm_utils.get_last_call_info()`. All rate limiting goes through **one shared sliding-window
limiter** (10 requests/60 s across chat + embeddings) — the flat `time.sleep(3)`s, the
per-classifier `time.sleep(1.5)`s and the off-by-one window guard are gone.

and the main window now share one piece of async UI plumbing (`ui/desktop/_async.py`:
`ProgressDialog`, `run_threaded`, `make_scrollable_tab`) rather than each carrying its own copy;
the Review tool inherits the **busy guard** (one background pass at a time), the mid-run `ask`
round-trip and the empty-folder cleanup for free. Its previously synchronous scans — **scan a
folder for storage spaces**, **import a bibliographic workbook**, and **scan a space's data
files** — now run on that background thread with progress + cancel instead of freezing the
window, and the window carries a `minsize` so the data-grid tabs are not crushed on resize.
**Every Review tab is now a vertical-scroll container** (the same `make_scrollable_tab` the main
window uses): the inner frame is kept at least as tall as the viewport, so expand-to-fill
treeviews still fill the tab when there is room and the outer scrollbar only engages once the
content genuinely overflows; the mouse wheel scrolls the tab except over a widget that scrolls
itself (treeview / text / listbox / inner canvas), which keeps its own wheel behaviour.

The CLI (`alr.ui.cli.pipeline`) exposes roughly the same Collect / Analyze / Visualize
surface (now with model selection), plus it is the only place the console API-key prompt runs.

## 3. Notable observations

- **Section editor** (`section_rewriter_view.py`) is now wired as Tab 4 (embedded + pop-out);
  it is no longer orphaned.
- **Provider selectors** exist on Collect and Analyze tabs, but the Visualize/Query and
  Review tabs are pure vector/DB work and need no LLM key (verified: no `llm_call` in the
  `rag_builders` query path).
- **Two entry points** (desktop + CLI) call the same backend; new backend features should be
  exposed through shared helpers so both stay in parity.
- Several backend scripts still contain **hard-coded absolute paths** in `__main__` blocks
  (e.g. `/remotedata/...`, `U:\...`); these are dev drivers, not used by the UI, but worth
  parameterizing if promoted into the app.
